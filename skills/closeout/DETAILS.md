## 参数与退出码

| 参数 | 作用 |
| --- | --- |
| `--handoffs <dir>` | 交接件台账目录（默认：工作区自己的 `handoffs/`；没有则 `~/.dsh/handoffs/<工作区名>/`，按工作区隔开） |
| `--handoff --task <名>` | 生成交接件骨架（默认不覆盖，`--force` 才覆盖） |
| `--report [--report-out <文件>]` | 生成收尾报告；只打到 stdout，`--report-out` 才写盘（相对路径按**工作区根**解析） |
| `--temp <dir>` / `--repo <dir>` | 指定临时目录 / 仓（可重复；默认 `./tmp` 与当前目录的一级仓） |
| `--hours N` | **强制**固定 N 小时窗口（默认按本段会话起点） |
| `--local <dir>` | 连带跑该工作区自己的门 |
| `--threshold N` / `--min-calls N` / `--token-threshold N` | 交接判据的覆盖开关（默认 300 / 50 / 0 = 关） |
| `--json` / `--strict` / `--explain` | 机读 / 有必须处理项时退出码 1 / 打印它自己的判定规则 |

退出码：正常 `0`；`--strict` 且有必须处理项 `1`；参数错误 `2`。

## 收尾·报告细则

只给**没有台账**的工作区：有台账的工作区，交接件就是唯一该产出的文档 —— 不要再单独写报告。
两份文档的内容是重复的（`做了什么` / `当前状态` / `未决` / `回滚点` 四节同源），
而报告独有的两节（结论、收尾·同步）都能用一条命令重新打出来。本机实测：`tmp\` 里堆了 12 份收尾报告，
没有任何交接件、成果登记或工作日志引用过它们 —— 既没人读，也不会被 tmp 清扫带走。

没有台账的工作区（外部项目、个人数据目录）反过来：报告是**唯一**能落盘的东西。

```bash
npx dsh-closeout --zh --report                            # 只打到 stdout（默认不写盘）
npx dsh-closeout --zh --report --report-out 收尾报告.md    # 要留档才写盘
```

- 六节：`结论` / `做了什么` / `当前状态（可复跑验证）` / `未决·下一步` / `收尾·同步（可选）` / `回滚点`；
- **不写 `原会话：` 行** —— 报告不参与 handoffs 台账，别和交接件混；
- `--report-out` 的**相对路径按工作区根解析，不是 cwd**（v0.7 起）。在 `tmp\<任务>\` 里收尾时，
  v0.6 会把它写进那个一次性目录。

## 落点：`handoffs/archive/`

**已完结交接件**（状态段改成 `已完成` / `已废弃`，件首状态块同步）移入 `<台账目录>/archive/`，**不存在则创建**
（`mkdir -p` / `New-Item -Force`，幂等）。`--status` 只扫一级 → 放进去即退出接力判定。工作区另有规定从其规定。

为什么用普通名词、不加 `_` / `.` 前缀（从"刚下完插件的用户"看）：

- `.` 开头：Unix 下 `ls` 与 GitHub 网页默认不显示、IDE 树里被折叠，等于把要人翻的归档藏起来；而 Windows 资源管理器**不认点号、只认 Hidden 属性**（本机实测 `.dsh` / `.pnpm-store` 都是 `Attributes=Directory`）→ 同一套命名在两个平台行为相反。
- `_` 开头：在生态里普遍是"私有 / 不参与常规处理"（Jekyll 不输出 `_posts`、Next.js 私有路由 `_folder`），与"归档仍要能点进去查证"相悖；还要额外解释"为什么是下划线"。
- `archive/`：与工具里常见的 `archive` 同词，一个普通名词，零解释成本；和台账里的 `（进行中）…` 件同处 `handoffs/`，关系一眼可见。

工作区可覆盖：`D:\dsh` 历史上把归档放在 `_archive\handoffs\`（不在 `handoffs/` 下），属本地覆盖；插件默认不为它改。

## 等待型件（有未来触发日期、现在无事可做）

2026-11-12 用户定。目的：这类件不能消失，但要在资源管理器里**排在普通「进行中」件下方**，一眼看出"还没轮到它"。

- 文件名：`（顺延·<YYYYMMDD>）（进行中）<YYYYMMDD>-<主题>.md`（前置字段 = 触发日期）；件首补一行 `> 顺延：等 <日期> 才动作`。
- 到期完结：删掉 `（顺延·…）` 前缀 → 正常改名 `（已完成）` → 归档。已完成件不留顺延前缀。
- **字段词只能用 `顺延` / `阻塞`**：12 个候选词实测三种排序口径 —— `cmd /c dir /on`（NLS/资源管理器）、
  PowerShell `Sort-Object`（.NET 文化排序）、node `readdirSync().sort()`（码点）：
  「等待 / 等 / 待办」按拼音（d、g）落在 `进行中`（jin）**上面**；「暂停 / 推迟」在 node 码点排序里
  （暂 U+6682、推 U+63A8 < 进 U+8FDB）落在**上面**；只有 `顺延`（U+987A）、`阻塞`（U+963B）三者全过。
- 工具无感：状态正则匹配文件名**任意位置**的 `（进行中|已完成|已废弃|参考）`（`legacy/sessions-handoff.mjs:216`），
  前置字段不影响 `--status`，仍应报「文件名状态段：齐全」。

## 反模式（都是真实踩过的）

1. **把"命令没报错"当成"生效了"** —— 退出码 0 + 空输出是最坏的一种，它看起来像成功。
2. **用"显式路径"提交就以为不会带走别人的改动** —— 同一个文件里别人的那几行会跟着一起进提交。
3. **以为归档会话 = 保存工作** —— 它只动列表，不动你的仓库，也不动你硬盘上的文件。
4. **把「不计入」当成"没查"** —— 那是查过后判定的"不是这个会话的"，别反过来替别的会话收尾。
5. **把收尾文档落进一次性目录** —— `tmp\<任务>\`、`_trash\` 是"可随手删"区，放在那里等于没写。
   落点按工作区根解析（v0.7）；没有台账的工作区，报告默认不写盘，要留档显式 `--report-out`。
6. **给同一个工作区写两份**（交接件 + 报告）—— 四节内容同源，报告独有的两节一条命令就能重打。

## 输出侧成本自检（2026-11-24 从 SKILL.md 移入，收尾时仍必做）

输出价是缓存命中价的 200 倍，是唯一值得每周盯的一项。工作区里有 `tools/output-check.mjs` 就跑（只读）：

```bash
node tools/output-check.mjs            # 最近 8 周 + 本周 vs 上周
node tools/output-check.mjs --json     # 机读
```

看**「输出/调用」**这一列，不看总输出（总输出跟着会话数走）：

- 环比涨 >10% → 在报告里记一行，并写明怀疑哪条：思考档位被升 / 长命令被重贴 / 正文在复述日志；
- 环比持平或下降 → 报告里一行「输出/调用 X，环比 ±Y%」就够，别展开。

后两条没法从台账计量，用下面两句做**本会话自查**（答「无」也要能举出反例才算查过）：

- 工具参数：本会话有没有 ≥800 字符的命令是**重贴**的（同一段脚本写了两遍以上）？有 → 说明该落文件；
- 可见正文：有没有整段复述日志 / 出现「完整内容如下」？有 → 下一条起只给结论、数字、差异、路径。

判定阈值在脚本里（本周/上周各 ≥100 次调用才判，未满周只报不判）。**不要**用 `--strict` 接到收尾流程里 ——
它 exit 1 会让收尾中断，而这项只是观察项。

## 关整个 DSH（app 口径）

`closeout app --zh` —— 另一条线，查的是应用而不是会话：运行中的实例 / 待重启标记 /
会话库整体有没有未收口的 / profile 的 bundles 重启后还装不装得上。结论三档：
`先别退出` / `可以退出；先确认 N 件事` / `可以直接退出`。`--handoff` / `--report` 不在这一口径产出。
