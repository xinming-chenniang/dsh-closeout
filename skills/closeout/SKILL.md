# 关会话之前：先体检，再交接，最后才关

会话是**最容易丢东西的时刻**：窗口一关，就没人在旁边提醒你"那个仓库还没提交""那个脚本只在你硬盘上"。
统一流程（2026-10-21）：**同步（可选）→ 体检 → 交接（按需）→ 报告 → 才允许关**。
旧词：**收口**=体检、**收工**=同步；总称「收尾」。

## 口令 → 入口（四条，别混）

| 用户说 | 走哪条 | 命令 |
| --- | --- | --- |
| 收尾 / 结束这个任务 / 归档这个会话 | 体检 + 按工作区形态产产物 | `closeout --zh` |
| 交接件 / 写交接 | 只产交接件 | `closeout handoff --zh --task <名>` |
| 收尾报告 / 出报告 | 只产报告（默认打到屏幕） | `closeout report --zh` |
| 关DSH / 关应用 / 退出前查一下 | 应用体检（只读，不杀进程） | `closeout app --zh` |

**点名的词优先**：用户只说「收尾」走第一条；说「收尾报告」就不要再顺手写交接件。

## 第 0 步：先跑体检，再判断要不要交接

不用自己估调用次数 —— `closeout` 读会话的**事件元数据**（调用次数、轮数、时间戳、末尾 reason、
以及工具调用参数里的路径），据此回答"该不该写交接件"和"哪些文件是这个会话自己写的"。
它**不读对话正文**（消息内容一行都不碰）。

读不到会话时（Node < 22 / 找不到会话文件），它会明说「这项没查」，并退回**时间窗**判断 ——
那种情况下同一时段别的会话写的也会被算进来，需要自己再看一眼。

## 第 0.5 步：收尾·同步（可选，先做）

改动**随时 commit**（`git add <显式路径>` → `git commit`），`push` 可以攒，不强制在收尾时做。
工作区有 `tools/dsh-sync.ps1` / `dsh-sync.sh` 时，用它的 `status` 看领先/落后（没有就跳过这一步）；
`push` 前先问用户。`--report` 生成的报告里会自动带上这条探测结果（只提示，不调用）。

## 第 0.7 步：超线先问一句

`closeout` 报「该写交接件」时，**先问**用户「要现在写交接件吗？」：

- 要 → 走第 3 步；
- 不要 → 记一次，本次会话不再提；同一会话的触发线**再涨 50%** 才第二次问（如 401 次 → 602 次）。

## 第 1 步：体检（一条命令）

```bash
npx dsh-closeout --zh                # 中文，结论在第一行
npx dsh-closeout handoff --zh --task <名>   # 体检 + 直接产交接件骨架
npx dsh-closeout report --zh         # 体检 + 打印收尾报告
npx dsh-closeout --zh --local .      # 连带本工作区自己的门（规则锁 / 根级登记 / 规则审计）
npx dsh-closeout app --zh            # 要关的是整个 DSH 时用这个口径
npx dsh-closeout --json              # 机读（钩子 / 脚本用）
```

> 子命令（`handoff` / `report` / `app`）**必须放在最前面**，在 `--zh` 这类选项之前。

> **工作区有自己的收尾脚本就先用它**（例如 `node tools\sessions-closeout.mjs`）：那是更完整的组合，
> `closeout` 只是它的判据层。两者结论不冲突时以工作区脚本为准。

它查这些，**全部只读**：

1. **仓库**：本会话的工具调用碰过的仓，有没有未提交 / 未推；别的会话留下的会写明「不计入」；
2. **临时目录**：本会话写了哪些文件（按会话自己的调用参数判归属）；同窗口别的会话写的明说个数、不计入；
3. **交接件台账**：该交接时，`handoffs/` 里有没有声明本会话的文件（认 `原会话：` 一行）；
4. **会话本身**：调用次数 / 上下文占用 / 跨天（按本段算）/ 末尾是否收口 / goal 是否 blocked；
5. **本机门（可选）**：`--local <dir>` 时跑那个工作区的规则锁 / 根级登记 / 规则审计。

输出长这样（结论在最上面，然后是四组清单）：

```
收口 —— 关会话之前的体检 · 会话 c177d2f2 · 183 次调用 · 跨 1 天 · 上下文 219k · 末次 2026-10-25 23:47
────────────────────────────────────────────
结论：✗ 可以归档；先别删 —— 还有 2 件东西只活在磁盘上

该不该交接：✓ 183 次调用 / 跨 1 天，未超线

必须处理：2
  ✗ D:\work\api → 1 已修改 / 2 未跟踪
      src/router.ts
  ✗ D:\work\tmp → 本段会话自 2026-10-25 22:55 起写了 3 个文件
      probe.ts  4 KB   [脚本]

不用管：2
  ✓ D:\work\legacy → 3 个提交没推，但本会话没提交/推送过它（之前留下的，不计入）
  ✓ D:\work\tmp：另有 12 个文件落在本段窗口内，但本会话的工具调用里没有（别的会话写的，不计入）

没查的（不等于没问题）：1
  · 本机侧的门（规则锁 / 根级登记 / 规则审计）没启用：加 --local <工作区> 才会查

只对「删除」设门槛：归档可逆，删除不可逆。
```

三档结论怎么读：

- `✓ 可以直接归档或删除` —— 没有本会话留下的东西；
- `! 可以归档；删之前先写交接件` —— 会话该交接但还没写；
- `✗ 可以归档；先别删` —— 还有本会话留下的东西只活在磁盘上。

**「不用管」里标「不计入」的不用处理** —— 那不是本会话弄的（别的会话 / 之前留下），别替它收尾；
只处理「必须处理」那几行。

## 第 2 步：把警告逐条处置（这一步不许跳过）

| 警告 | 处置 |
|---|---|
| 本会话碰过的仓有未提交改动 | 提交（写清为什么），或 `git stash` 并记在交接件里。**不要**指望"归档会话"替你保存 |
| 本会话写的临时文件 | **默认直接清掉，不再逐次问用户**（2026-11-11 用户定「每次收尾自动删」）：`node D:\dsh\tools\closeout-clean.mjs --apply` —— 它只删「本会话写、且在 `--temp` 根内」的文件，`otherTotal`（别会话 / 更早留下的）一律不动；值得留的先移进项目目录 / 归档区。工作区 `AGENTS.md` 若规定先入 `_trash` 缓冲，加 `--trash` |
| 领先上游 | push，或者明确写下"故意没推，原因 …" |
| 落后上游 | pull / rebase 之后再收尾（先别改，先对齐） |
| 标「不计入」的 | **不用处理**（不是这个会话的遗留） |

**两个不许擅自做的动作**：

- **推送**（`git push`）是外部可见的。工具报出"没推的提交"时，**先问一句"要我推吗"**，得到确认再推；
  被远端拒绝时别改用 `--force`，先看远端到底有什么。
- **删除**临时文件：按上表**默认自动清**（用户 2026-11-11 改的口径：收尾即删，不再逐次确认）——
  用 `node D:\dsh\tools\closeout-clean.mjs --apply`，归属白名单取自 `closeout --json`；
  **只删本会话写的一次性文件**，`otherTotal` / 别人的东西一律不动；删完把脚本打印的清单贴出来。

停在这里问一句：**"如果这个会话今天就消失，上面这些还能重建吗？"** 答不上来就还没收尾完。

## 第 3 步：交接件（给下一个会话看的，不是给自己看的；**只给有台账的工作区**）

先让工具生成骨架，别从空白写：

```bash
npx dsh-closeout --handoff --task <任务名>
```

> **落点不用自己拼**：工作区有 `handoffs/` 就写进去；没有就落到 `~/.dsh/handoffs/<工作区名>/`（按工作区隔开）。
> 要写别处才加 `--handoffs <dir>`。本机 `D:\dsh` 的台账是 `D:\dsh\handoffs`；**别的台账（如 `D:\个人项目\handoffs`）跑 `--status` 必须显式 `--handoffs <dir>`**，否则只看得到 `D:\dsh` 那一份。

骨架是**七节**：`目标` / `做了什么` / `当前状态（可复跑验证）` / `关键文件` / `未决·下一步` / `开放问题` / `回滚点`。
其中 `当前状态`（仓 + 临时文件 + 会话长度）、`关键文件`（未提交清单前 10 个）、`目标`（会话标题）工具已填，
你补四节：**做了什么 / 未决·下一步 / 开放问题 / 回滚点**（目标那句也顺手改成人话）。

```markdown
# <任务名> · 交接（<日期>）

> 状态：进行中
> 更新：<YYYY-MM-DD HH:mm>
> 完成判据：<一句话 —— 达成它就算完结>
> 原会话：<id 或"无">

> ⚠️ **状态词只有三个**：`进行中` / `已完成` / `已废弃`。别写「已收口」「卡住」「基本完成」——
> 工具只对旧写法做兼容兜底；文件名里的状态段与件首状态块必须一致，改状态时两处一起改。

## 目标
（一行：这个会话要达成什么）

## 做了什么
（3–6 条，一行一条，带证据：命令 + 实际输出）

## 当前状态（可复跑验证）
（工具已填；已验证 / 未验证分开写，验证命令必须能直接复制）

## 关键文件
（改了哪些文件、为什么关键）

## 未决 / 下一步
（接手的人第一步该干什么；不要写"继续完善"这种没有动作的话）

## 开放问题
（接手的人会卡住的地方：没定的事、没验证的假设、需要问用户的决定）

## 回滚点
（改了哪些东西、怎么退回；没有就写"无"）
```

默认**不覆盖**已有文件（要覆盖加 `--force`）—— 覆盖交接件 = 丢掉别人写的东西。

**写完必须自检（2026-11-09 定为必做）**：状态只写正文行内不算 —— 文件名要有状态段、件首要有三行块。跑：

```bash
node D:\dsh\plugins\dsh-closeout\legacy\sessions-handoff.mjs --status --handoffs <台账目录>
```

期望 `未标注 0` 且**没有** `⚠ 文件名缺状态段`；有 ⚠ 就当场改名/补块再跑一次。事故经过见 `handoffs\README.md` ③。

## 第 3.5 步：收尾·报告（只给**没有台账**的工作区）

**先看工作区有没有 `handoffs/`**：有台账的工作区，交接件就是唯一该产出的文档 —— 不要再单独写报告。
两份文档的内容是重复的（`做了什么` / `当前状态` / `未决` / `回滚点` 四节同源），
而报告独有的两节（结论、收尾·同步）都能用一条命令重新打出来。本机实测：`tmp\` 里堆了 12 份收尾报告，
没有任何交接件、成果登记或工作日志引用过它们 —— 既没人读，也不会被 tmp 清扫带走。

没有台账的工作区（外部项目、个人数据目录）反过来：报告是**唯一**能落盘的东西。

```bash
npx dsh-closeout --zh --report                            # 只打到 stdout（默认不写盘）
npx dsh-closeout --zh --report --report-out 收尾报告.md    # 要留档才写盘
```

- 六节：`结论` / `做了什么` / `当前状态（可复跑验证）` / `未决·下一步` / `收尾·同步（可选）` / `回滚点`；
- **不写 `原会话：` 行** —— 报告不参与 handoffs 台账，别和交接件混；
- `--report-out` 的**相对路径按工作区根解析，不是 cwd**（v0.7 起）。在 `tmp\<任务>\` 里收尾时，
  v0.6 会把它写进那个一次性目录。

**判据一句话**：一个工作区只产出一份文档 —— 有台账就是交接件，没台账就是报告。

## 第 4 步：才允许关

- **归档**是可逆的（东西还在，只是从列表里挪走）→ 体检做完、该产出的那一份文档落盘后就可以归档；
- **删除**是不可逆的 → 必须满足两条：第 2 步警告清零、第 3 步交接件已落盘。

## 第 5 步：要关的是**整个 DSH**（不是这个会话）

`closeout app --zh` —— 另一条线，查的是应用而不是会话：运行中的实例 / 待重启标记 /
会话库整体有没有未收口的 / profile 的 bundles 重启后还装不装得上。结论三档：
`先别退出` / `可以退出；先确认 N 件事` / `可以直接退出`。`--handoff` / `--report` 不在这一口径产出。

## 参考：常用参数与退出码

| 参数 | 作用 |
|---|---|
| `--handoffs <dir>` | 交接件台账目录（默认：工作区自己的 `handoffs/`；没有则 `~/.dsh/handoffs/<工作区名>/`，按工作区隔开） |
| `--handoff --task <名>` | 生成交接件骨架（默认不覆盖，`--force` 才覆盖） |
| `--report [--report-out <文件>]` | 生成收尾报告；只打到 stdout，`--report-out` 才写盘（相对路径按**工作区根**解析） |
| `--temp <dir>` / `--repo <dir>` | 指定临时目录 / 仓（可重复；默认 `./tmp` 与当前目录的一级仓） |
| `--hours N` | **强制**固定 N 小时窗口（默认按本段会话起点） |
| `--local <dir>` | 连带跑该工作区自己的门 |
| `--threshold N` / `--min-calls N` / `--token-threshold N` | 交接判据的覆盖开关（默认 300 / 50 / 0 = 关） |
| `--json` / `--strict` / `--explain` | 机读 / 有必须处理项时退出码 1 / 打印它自己的判定规则 |

退出码：正常 `0`；`--strict` 且有必须处理项 `1`；参数错误 `2`。

## 反模式（都是真实踩过的）

1. **把"命令没报错"当成"生效了"** —— 退出码 0 + 空输出是最坏的一种，它看起来像成功。
2. **用"显式路径"提交就以为不会带走别人的改动** —— 同一个文件里别人的那几行会跟着一起进提交。
3. **以为归档会话 = 保存工作** —— 它只动列表，不动你的仓库，也不动你硬盘上的文件。
4. **把「不计入」当成"没查"** —— 那是查过后判定的"不是这个会话的"，别反过来替别的会话收尾。
5. **把收尾文档落进一次性目录** —— `tmp\<任务>\`、`_trash\` 是"可随手删"区，放在那里等于没写。
   落点按工作区根解析（v0.7）；没有台账的工作区，报告默认不写盘，要留档显式 `--report-out`。
6. **给同一个工作区写两份**（交接件 + 报告）—— 四节内容同源，报告独有的两节一条命令就能重打。
