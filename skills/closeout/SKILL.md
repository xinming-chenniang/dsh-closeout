# 关会话之前：先体检，再交接，最后才关

会话是**最容易丢东西的时刻**：窗口一关，就没人在旁边提醒你"那个仓库还没提交""那个脚本只在你硬盘上"。
这个技能就是那声提醒，统一流程（2026-10-21）：**同步（可选）→ 体检 → 交接（按需）→ 报告 → 才允许关**。
旧词对照：**收口** = 体检这一步；**收工** = 同步这一步；总称统一叫「收尾」。

## 第 0 步：先跑体检，再判断要不要交接

不用自己估调用次数了 —— `closeout` 会读会话的**事件计数**（只看次数与时间，不读对话正文），
直接给出"该不该写交接件"。只有当它读不到会话时（Node < 22，或找不到会话文件），才需要你自己拿运行时读数判断。

## 第 0.5 步：收尾·同步（可选，先做）

改动**随时 commit**（`git add <显式路径>` → `git commit`），`push` 可以攒，不强制在收尾时做。
工作区有 `tools/dsh-sync.ps1` / `dsh-sync.sh` 时，用它的 `status` 看领先/落后；`push` 前先问用户。
`--report` 生成的报告里会自动带上这条探测结果（只提示，不调用）。

## 第 0.7 步：超线先问一句

`closeout` 报「该写交接件」时，**先问**用户「要现在写交接件吗？」：

- 要 → 走第 3 步；
- 不要 → 记一次，本次会话不再提；同一会话的触发线**再涨 50%** 才第二次问（如 401 次 → 602 次）。

这条来自同类插件的实测做法（拒绝后冷却），目的只有一个：不让提醒变成骚扰。

## 第 1 步：体检（一条命令）

```bash
npx dsh-closeout                          # 英文标签
npx dsh-closeout --zh                     # 中文（结论在最上面一行）
npx dsh-closeout --zh --temp ./tmp --hours 6 --local .
npx dsh-closeout --zh --token-threshold 150000   # 上下文超 150k 也算「该交接」
```

它查四件事，都只读：

1. **每个仓库有没有没提交的改动**（暂存 / 修改 / 未跟踪分开数，并列出文件名）；
2. **配置的临时目录里有没有刚写出来的文件**（默认 `./tmp`，`--hours` 控制"多新算新"）；
3. **每个仓库相对上游领先/落后多少**（忘了 push 的提交；没配上游时会明说"无法判断"）；
4. **这个会话该不该交接**（调用次数 / 上下文占用 / 跨天 / 末尾是否收口 / goal 是否 blocked）。

输出示例：

```
仓库:
  ! D:/dsh/dsh-worklog  [main]  未跟踪 1
      output/dsh-lore-vs-worklog/
  + D:/dsh/skills-src  [master]  干净

最近写出来的文件 (last 6h):
  ! D:\dsh\tmp
      attention.json  55 KB

汇总: 2 警告
```

**为什么它不读会话日志**：会话日志格式是各家私有的、没有兼容承诺；解析它等于给用户埋一颗"升级即静默失效"的雷。磁盘上的事实（git、文件）才是跨天跨版本都稳定的判据。

## 第 2 步：把警告逐条处置（这一步不许跳过）

| 警告 | 处置 |
|---|---|
| 仓库有未提交改动 | 提交（写清为什么），或 `git stash` 并记在交接件里。**不要**指望"归档会话"替你保存 |
| 临时目录有新文件 | 值得留的移进项目目录/归档区；一次性的明确删掉。**不要**留给"以后再说" |
| 领先上游 | push，或者明确写下"故意没推，原因 …" |
| 落后上游 | pull / rebase 之后再收尾（先别改，先对齐） |

**两个不许擅自做的动作**：

- **推送**（`git push`）是外部可见的。工具报出"没推的提交"时，**先问一句"要我推吗"**，得到确认再推；
  被远端拒绝时别改用 `--force`，先看远端到底有什么。
- **删除**临时文件：先把清单列给人看，让人确认哪些是一次性的 —— 工具只负责说出来，不替你删。

停在这里问一句：**"如果这个会话今天就消失，上面这些还能重建吗？"** 答不上来就还没收尾完。

## 第 3 步：交接件（给下一个会话看的，不是给自己看的）

先让工具生成骨架，别从空白写：

```bash
npx dsh-closeout --handoff --task <任务名> --handoffs ./handoffs
```

它已经把**工具知道的事实**填进「当前状态（可复跑验证）」——会话 id、调用次数、跨天、未提交的仓、
临时文件清单。你只写三节：**做了什么 / 未决·下一步 / 回滚点**。

填完长这样（四段式）：

```markdown
# <任务名> · 交接（<日期>）

> 原会话：<id 或"无"> · 状态：进行中 / 已收口 / 卡住

## 做了什么
（3–6 条，一行一条，带证据：命令 + 实际输出）

## 当前状态（可复跑验证）
（哪些是已验证的、哪些是未验证的；验证命令必须能直接复制）

## 未决 / 下一步
（接手的人第一步该干什么；不要写"继续完善"这种没有动作的话）

## 回滚点
（改了哪些东西、怎么退回；没有就写"无"）
```

## 第 3.5 步：收尾·报告（必做）

```bash
npx dsh-closeout --zh --report                        # 打印四段骨架
npx dsh-closeout --zh --report --report-out 收尾报告.md  # 写盘
```

四段：做了什么 / 当前状态（可复跑验证）/ 未决·下一步 / 回滚点。
它**不写 `原会话：` 行** —— 报告不参与 handoffs 台账，别和交接件混。

## 第 4 步：才允许关

- **归档**是可逆的（东西还在，只是从列表里挪走）→ 体检 + 报告做完就可以归档；
- **删除**是不可逆的 → 必须满足两条：第 2 步警告清零、第 3 步交接件已落盘。

## 第 5 步：要关的是**整个 DSH**（不是这个会话）

`closeout app --zh` —— 另一条线，查的是应用而不是会话：运行中的实例 / 待重启标记 /
会话库整体有没有未收口的 / profile 的 bundles 重启后还装不装得上。结论三档：
`先别退出` / `可以退出；先确认 N 件事` / `可以直接退出`。`--handoff` / `--report` 不在这一口径产出。

## 反模式（都是真实踩过的）

1. **把"命令没报错"当成"生效了"** —— 退出码 0 + 空输出是最坏的一种，它看起来像成功。
2. **用"显式路径"提交就以为不会带走别人的改动** —— 同一个文件里别人的那几行会跟着一起进提交。
3. **以为归档会话 = 保存工作** —— 它只动列表，不动你的仓库，也不动你硬盘上的文件。
